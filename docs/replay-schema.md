# LLM Replay — data contract v1

Every artifact below is generated by `generators/replay_generator.py` and written to
`web/data/{date}/`. This document is the **shared contract**: the capture layer, the
generator, and the frontend all code against it. Change it here first.

## Design principle

The replay is not a log viewer. It is a **reconstruction of the pipeline as a cast of
agents doing work over time**. Every animation on screen must be backed by a real
timestamp from a real request — no decorative motion. If we can't measure it, we don't
draw it.

## Timebase

All times are **integer milliseconds since run start** (`t0`). Monotonic, small,
gzip-friendly. `t0` itself is one absolute ISO timestamp at the top of the index.
Never store absolute times per event.

## Artifacts

| File | Size target | Committed | Purpose |
|---|---|---|---|
| `replay-index.json` | 15–60 KB | yes, permanent | Everything needed to render the theater, Gantt, and funnel. No prose content. |
| `replay-stream.json.gz` | ≤ 600 KB gzipped (hard cap) | yes, prunable | Per-call token deltas for typewriter playback. |

The index is self-sufficient: **if the stream file is missing or fails to load, the
replay still fully works** — it just loses the typewriter. The frontend must treat the
stream as an optional enhancement, fetched lazily only when a user opens a call.

Retention is by **size, not age**: a pruning script may delete `replay-stream.json.gz`
for older dates. The index stays forever.

### Serving `.json.gz`

Fetched as an `ArrayBuffer` and inflated in-browser with `DecompressionStream('gzip')`.
This needs **no nginx change** and works with the dev Vite middleware
(`application/octet-stream` is fine). Do not rely on transport-level `Content-Encoding`.

### Derivation rules

**`agent_id` / `task` / `role` from `caller`** — deterministic table, one place
(`agents/replay_taxonomy.py`), used by the generator only. Never guessed in the frontend.

| caller pattern | agent_id | role | task |
|---|---|---|---|
| `{cat}_analyzer.batch_{n}` | `{cat}_analyzer` | `map` | `Analyze batch {n}` |
| `{cat}_analyzer.batch_{n}_retry` | `{cat}_analyzer` | `map` | `Retry batch {n}` |
| `{cat}_analyzer.reduce_rank` | `{cat}_analyzer` | `reduce` | `Rank and select` |
| `news_analyzer.filter` | `news_analyzer` | `filter` | `Pre-filter articles` |
| `news_analyzer.small_batch` | `news_analyzer` | `map` | `Analyze (small batch)` |
| `continuity.matcher.{cat}` | `continuity` | `match` | `Match {cat} to prior days` |
| `continuity.curator` | `continuity` | `curate` | `Curate storylines` |
| `freshness.old_anchor` | `freshness` | `check` | `Check anchor freshness` |
| `orchestrator.topics` | `orchestrator` | `synthesize` | `Detect cross-category topics` |
| `orchestrator.summary` | `orchestrator` | `synthesize` | `Write executive summary` |
| `link_enricher.{ctx}` | `link_enricher` | `enrich` | `Link {ctx}` |
| `ecosystem_context.enrichment` | `ecosystem` | `enrich` | `Detect model releases` |

Unknown callers **must not** be dropped — fall back to
`agent_id = caller.split('.')[0]`, `role = "map"`, `task = caller`. The taxonomy failing
open matters more than it being complete.

**`worker`** — parsed from `batch_{n}`; `3a`/`3b` splits become worker `3` with a
`split` suffix in `task`. Null for non-batch calls.

**`phase_id`** — resolved by wall-clock containment against `PhaseTracker` absolute
timestamps. `PhaseTracker.to_dict()` currently drops absolute times; the generator reads
the live tracker object instead, so no serialization change is required.

## `replay-stream.json.gz`

Inflates to:

```jsonc
{
  "schema": 1,
  "date": "2026-07-28",
  "calls": {
    "c017": {
      // Deltas as three parallel arrays — far smaller gzipped than an array of objects.
      // kind: 0 = thinking, 1 = text
      "t":    [18630, 18742, 18901],   // ms since run start
      "kind": [0, 0, 1],
      "text": ["I need to", " group these by", "## Research"]
    }
  }
}
```

Rules:

- **Monotonic `t`.** Clamp any regression to the previous value.
- **Coalescing.** Merge consecutive same-kind deltas inside a `coalesce_ms` window
  (default 80 ms). One SSE event per token is far more resolution than a human eye needs;
  80 ms preserves a natural typewriter feel at 1× while cutting volume ~5×.
- **Never store `signature_delta`.** It is a cryptographic blob, useless to render.
- **Thinking is included and is the point.** Verified against the live endpoint: with
  `display: "summarized"`, Opus 5 emits real `thinking_delta` prose ahead of the text
  block. It is a *summary* of reasoning, not raw chain-of-thought, and it is sometimes
  short — the UI must degrade gracefully when a call has zero thinking chars.

### Hard size cap

The generator enforces ≤ 600 KB gzipped by escalating in order, logging each step:

1. Coalesce at 80 ms (default).
2. Coalesce at 250 ms.
3. Keep full deltas for *marquee* calls (`role` in `synthesize`/`reduce`/`curate`) and
   store only thinking for the rest.
4. Keep marquee only; set `has_stream: false` on the others.

Truncation is never silent — the index carries `run.stream_truncation` describing which
step fired.

## Capture layer contract

`agents/replay_recorder.py`, an **observer** attached to the existing streaming path.

Non-negotiables, in priority order over completeness:

1. **The pipeline must never fail because of replay.** Every recorder entry point is
   wrapped; on first exception the recorder disables itself for the rest of the run and
   logs one warning. A broken replay is a missing feature, never a failed build.
2. **Memory only on the hot path.** No file I/O, no locks, no `await` inside the SSE
   loop. Buffers flush once at end of run.
3. **Bounded.** Per-call delta cap (default 20 000 entries) and a global cap; overflow
   sets a `truncated` flag rather than growing without limit.
4. **Off by default in dev, on in CI.** `LLM_REPLAY_CAPTURE` (default `true`),
   `LLM_REPLAY_COALESCE_MS` (default `80`), `LLM_REPLAY_MAX_BYTES` (default `600000`).
5. **Prompts are captured and published; credentials never are.** The prompt each call
   sent is recorded off the hot path (once per call, in `start_call`, never inside the
   SSE loop) and published as `replay-prompts.json.gz`. This project is a showcase and
   is fully open source — `config/prompts.yaml`, the analyzers and the workflows are
   already public — so the instructions the models were given are part of what the
   replay exists to show.

   What must never appear is a credential or a private endpoint host.
   `replay_generator._assert_publishable` enforces that over the prompt artifact as
   well as the index, and it is load-bearing here in a way it was not before: prompts
   embed *collected third-party text* (Reddit comments, article bodies), so unlike the
   index they are not a closed set of known fields.

   Prompts are bounded like deltas — `LLM_REPLAY_MAX_PROMPT_CHARS` per call,
   `LLM_REPLAY_MAX_TOTAL_PROMPT_CHARS` per run — and truncation is always marked, never
   silent. `LLM_REPLAY_CAPTURE_PROMPTS=false` disables capture without losing the
   timeline.

## Privacy / publication

This project is fully open and the artifacts are committed publicly. That is safe here
because the replay contains **only model output plus timing/token metadata** — no
prompts, no API keys, no endpoint hostnames, no request bodies. `provider_id` is an
opaque route label (`aws`/`gcp`/`anthropic`), not a URL. The generator asserts no field
matches a secret-shaped pattern before writing.
